# 용어 결정 기준

## 결정 순서

1. **팀 용어집**: 저장소의 [`docs/GLOSSARY.md`](../../../../docs/GLOSSARY.md)를 먼저 따릅니다. 팀에서 정한 번역이 다른 자료보다 우선합니다.
2. **새 용어**는 아래 판단 기준으로 표기를 제안합니다. PR 본문의 “검토가 필요한 표현”에 `영어 → 선택한 번역 (근거)` 형식으로 적습니다.
3. 리뷰에서 표기가 확정되면 팀 용어집에 추가합니다.

## 판단 기준

| 경우 | 쓰는 방식 | 예 |
| --- | --- | --- |
| 한국어로 정착한 말 | 익숙한 한글 음차를 포함해 한국어로 씁니다. | 요청, 할당, 메모리, 배치, KV 캐시, 토크나이저 |
| 고유한 기술 용어와 코드 식별자 | 영어 그대로 씁니다. | MoE, Expert, AdamW, `tie_word_embeddings` |
| 번역어가 덜 알려진 용어 | 한국어로 쓰고 본문에서 처음 나올 때만 괄호 안에 영어를 병기합니다. | 밀집 모델(dense model), 중간 학습(mid-training) |

- 한 번 정한 표기는 담당 범위 전체에서 통일합니다. 같은 개념에 “손실”과 `loss`를 섞지 않습니다.
- 논문·모델·도구 이름을 부분 치환하지 않습니다. `Dataset` 하나만 한국어로 바뀐 영문 논문 제목은 허용하지 않습니다.
- 문맥에 따라 뜻이 달라지는 단어를 구분합니다. `reasoning`은 사람의 사고와 모델의 추론 능력, `compute`는 연산량·연산 비용·연산 자원 중 문맥에 맞게 옮깁니다.
- 기계적인 전역 치환은 수식 아래첨자, URL, 논문 제목까지 손상시킬 수 있으므로 사용하지 않습니다.

## 괄호와 약어

- 번역 문장에서 괄호는 영문 병기와 약어 정의에만 씁니다. 보충 설명은 문장에 풀어 씁니다. 예를 들어 “사전 학습을 이어 하는 방법인 중간 학습(mid-training)”처럼 씁니다.
- 한국어 표기가 있는 용어의 약어를 소개할 때는 첫 등장에 **텐서 병렬화(TP)**처럼 쓰고 이후에는 **TP**로 씁니다.
- 영어로 쓰는 기술 용어의 약어를 소개할 때는 첫 등장에 **Direct Preference Optimization(이하 DPO)**처럼 쓰고 이후에는 **DPO**로 씁니다. 용어집에 첫 등장 표기가 정해져 있으면 그 표기를 따릅니다.

## 영한 혼용 줄이기

일반 개념과 동사까지 영어로 남기지 않습니다.

| 피할 표현 | 문맥에 맞는 표현 |
| --- | --- |
| `learning 용량`, `추론 time` | 학습 용량, 추론 시점·추론 시간 |
| `deployment constraints` | 배포 제약·제약 조건 |
| `The 토크나이저`, `Measuring 토크나이저 Quality` | 토크나이저, 토크나이저 품질 측정하기 |
| `loss`, `optimizer`, `context`, `downstream task` | 손실, 옵티마이저, 컨텍스트, 후속 과제 |
| `at scale` → “규모에서” | 대규모에서·규모를 키웠을 때 |
| `compute scales linearly with size` | 연산량이 모델 크기에 비례해 증가합니다. |
| `the whole post-training alphabet` | SFT, DPO, GRPO를 비롯해 여러 약어로 불리는 사후 학습 기법 |

## 아직 정하지 않은 용어

- `ablation`의 표기 후보는 “어블레이션”, “절제 실험”, “제거 실험”입니다. 팀이 정하기 전에는 첫 등장에 영어를 병기하고 PR에 선택 근거를 적습니다.
