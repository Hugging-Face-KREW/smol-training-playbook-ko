# Playbook 한국어 번역

Hugging Face의 설명과 경험을 한국어 독자가 자연스럽게 읽도록 옮깁니다. 이 skill은 **From Smol to Ultra Scale 스터디 전용**입니다.

## 작업 범위와 기준

먼저 현재 저장소의 `TRANSLATION_GUIDE.md`와 해당 교재의 배정표를 읽습니다. 저장소의 최신 명시적 지침과 사용자의 요청을 우선하며, 이 skill과 충돌하면 차이를 알리고 적용할 기준을 확인합니다.

Smol의 현재 경로는 다음과 같습니다. 실제 파일이 존재하는지 확인한 뒤 사용합니다.

- 고정 영문 원문 — `docs/original/article.en.mdx`
- 수정할 번역본 — `app/src/content/article.mdx`
- 본문·그림 배정표 — `docs/SMOL_TRANSLATION_ASSIGNMENTS.md`
- 인터랙티브 그림 — `app/src/content/embeds/`
- 저장소 — [Smol 한국어 번역 프로젝트](https://github.com/Hugging-Face-KREW/smol-training-playbook-ko)

Ultra는 이 경로와 주차를 그대로 추정해 적용하지 않습니다. 현재 가이드·배정표에서 실제 원문, 번역 파일, 그림 목록, 범위를 확인합니다. 정해지지 않았거나 찾을 수 없다면 필요한 정보를 묻습니다. 최신 웹 원문보다 프로젝트에서 정한 고정 원문을 대조 기준으로 사용합니다.

입력은 교재, 주차 또는 섹션, 원문·번역 경로, 양 끝을 포함한 원문 줄 범위입니다. 주차만 주어지면 배정표에서 찾고, 여러 구간이면 각각 기록합니다. 함께 맡은 그림과 공용 그림의 담당도 확인합니다. 자동으로 전체 책을 처리하지 않습니다.

- **번역·교정 요청** — 승인된 본문 줄과 배정된 그림 파일만 수정하고 검증합니다.
- **리뷰 요청** — 원문과 번역을 읽고 발견 사항만 보고합니다. 수정 요청이 없으면 파일을 바꾸지 않습니다.
- 담당 범위와 작업 유형이 명확하면 반복해서 승인을 묻지 않습니다. 커밋·push·PR·댓글·머지·배포는 별도 실행 요청이 있을 때만 수행합니다.

## 한국어 문체

번역 또는 교정 전에 [문체와 실제 교정 예시](references/style.md)와 [용어 결정 기준](references/terms.md)을 읽습니다.

- **읽기 편한 번역이 우선입니다.** 영어 문장 구조를 그대로 옮기지 않고, 한국어 독자가 한 번에 읽을 수 있게 어순·주어·품사를 바꿉니다. 원문의 주장, 조건, 수치, 확신의 정도, 유머는 바꾸지 않고, 원문에 없는 설명을 더하거나 요약하지 않습니다.
- 본문은 **“-습니다 / -입니다” 설명체**입니다. 권유는 “-하세요 / -보세요”, 질문은 “-까요?” 등을 자연스럽게 사용합니다. 저자는 “우리”, 독자는 “여러분”으로 둡니다. 과한 격식이나 “저희”는 피합니다.
- `it`, `this`, `they` 같은 대명사는 “그것”, “이것”, “그들”로 옮기지 않습니다. 앞 문맥에서 확인되는 대상을 명사로 다시 쓰거나 생략합니다. 지시 대상이 애매하면 추측하지 말고 PR에 적습니다.
- 무생물 주어와 수동태는 한국어 문장으로 바꿉니다. 긴 문장은 **같은 줄 안에서** 여러 문장으로 나눠도 됩니다.
- 한국어에서 쌍점(:)은 표제 뒤, 시간·비율, 코드·URL에만 씁니다. 영어처럼 문장을 잇는 콜론은 연결어나 문장 분리로 바꿉니다. 범위는 `1-3`처럼 하이픈으로 씁니다.
- 기술 용어는 **팀 용어집([`docs/GLOSSARY.md`](../../../docs/GLOSSARY.md)) → terms.kr → 판단 기준** 순서로 정합니다. terms.kr는 `scripts/lookup_terms.py`로 조회합니다. 둘 다 없는 용어는 선택 근거를 PR 본문에 적습니다. 한 번 정한 표기는 담당 범위 전체에서 통일합니다.
- 논문·모델·도구 이름은 부분 치환하지 않습니다. URL·코드·수식·원제의 문법은 이 문체 규칙으로 바꾸지 않습니다.

## 원문 한 줄 ↔ 번역 한 줄

**전체 줄 수만 같으면 된다는 뜻이 아닙니다. 각 물리적 줄의 내용과 빈 줄 위치가 원문과 대응해야 합니다.**

- 담당 원문 Lx의 설명은 번역본 Lx에 둡니다. 긴 문장도 실제 줄을 나누지 않습니다. 화면에서만 접는 soft wrap은 사용해도 됩니다.
- 빈 줄을 넣거나 지우지 않습니다. 문단을 합치거나 나누거나, 문장을 다른 줄로 옮기거나 재배열하지 않습니다.
- 전체 파일 자동 포맷팅과 줄바꿈 정리를 하지 않습니다. 원본 파일의 줄 끝 형식도 유지합니다.
- 리뷰 suggestion은 선택한 줄과 동일한 줄 수·빈 줄 구조를 사용합니다.
- 원문·번역이 이미 어긋나 있으면 파일 전체를 재정렬하지 않습니다. 불일치 위치를 보고하고 필요한 복구 범위를 확인합니다.
- 줄을 늘리는 역주·검토 메모는 본문에 추가하지 않습니다. 애매한 해석과 원문 결함은 대화나 요청된 리뷰 결과에 따로 적습니다.

## 본문·그림에서 보존할 것

- 코드 블록, 명령어, 실험 입력·출력, 수식과 기호, 수치·단위, 인용 키, 식별자, URL, import, 파일 경로를 보존합니다. 코드 주석도 이번 번역에서 별도 요청이 없다면 유지합니다.
- MDX 컴포넌트·태그·속성 이름과 문법을 유지합니다. `title`, `caption`, `alt`와 config 값 중 **독자에게 보이는 자연어**만 번역합니다. 데이터 키·선택자·모델명은 바꾸지 않습니다.
- 표·각주·캡션·사이드노트도 담당 본문의 일부입니다. 범위 밖 링크 수정이 필요하면 별도 항목으로 보고하며, Obsidian wikilink로 바꾸지 않습니다.
- **anchor는 원문의 영문 id를 유지합니다.** 사이트는 같은 줄 번호에 있는 원문 heading의 id를 그대로 사용합니다(`app/plugins/remark/source-heading-ids.mjs`). heading 문장은 자유롭게 번역하되 `#` 개수는 바꾸지 않고, 내부 링크(`](#the-training-marathon)`)의 대상도 바꾸지 않습니다. `{#...}` 같은 별도 표기는 필요하지 않습니다.
- 담당 HTML 그림은 제목·축·범례·툴팁·버튼 등 화면 문구를 번역합니다. HTML/JavaScript 구조, 데이터 키, 수치, 계산 로직은 보존합니다. 공용 파일은 배정표에서 담당과 영향을 확인한 뒤 수정합니다.
- 외부 iframe의 URL과 동작은 유지하고 주변 설명·캡션만 번역합니다. 외부 화면을 직접 수정하거나 MDX 임베드를 링크 전용 콜아웃으로 바꾸지 않습니다.
- 원문 자체의 수식 불일치·오탈자·숫자 모순을 번역 오류로 집계하지 않습니다. 본문 수치·코드·수식은 임의로 고치지 말고, 정확한 원문 위치와 근거를 따로 보고합니다. 원문 수정이 승인되면 그 범위에서만 반영합니다.

## 원문 대조와 검증

수정 전 번역본을 저장소 밖 임시 파일에 그대로 보관해 변경 범위를 대조합니다. 영문 원본은 수정하지 않습니다.

1. 담당 구간 **전체**를 원문과 같은 줄끼리 대조합니다. 길면 나누어 읽고, 실제 확인한 범위를 기록합니다. 일부 예시 점검만으로 전체 대조 완료라고 보고하지 않습니다.
2. 부정·조건·비교·인과·주체·규모·확신의 정도·수치·단위를 확인합니다. 생략이나 원문에 없던 설명이 없는지, 제목·표·각주·그림 문구가 빠지지 않았는지 봅니다.
3. 아래 도구로 본문의 물리적 줄 대응과 보호 대상을 검사합니다. 여러 범위는 `--range`를 반복합니다. `--before`는 작업 직전 번역본 사본입니다. 경로와 범위는 실제 입력으로 바꿉니다.

```bash
python3 .agents/skills/playbook-translate/scripts/check_translation.py \
  --source docs/original/article.en.mdx \
  --translation app/src/content/article.mdx \
  --before /tmp/article-before.mdx \
  --range 1402:2054
```

검사 결과는 두 종류입니다.

- **FAIL**은 팀 규칙 위반이며 종료 코드 1을 반환합니다. 모두 고친 뒤 다시 실행합니다. 검사 대상은 줄 수, 빈 줄 위치, 줄 끝, heading 단계, 담당 범위 밖 변경, 코드 블록·수식·import 줄, frontmatter의 키와 고정 값, JSX 태그와 속성 이름, 번역하지 않는 속성 값(`src`, `href`, `variant` 등), config의 키와 고정 값(`metric`, `dataUrl` 등), URL, 링크 대상, 인라인 코드와 수식, 인용 키, 각주입니다. 순서는 따지지 않으므로 한국어 어순에 맞춰 위치를 옮겨도 됩니다.
- **WARN**은 사람이 판단할 항목이며 실패로 처리하지 않습니다. 영어 그대로 남은 줄(`untranslated`), 숫자 불일치(`number`), “그것/이것/그들”(`pronoun`), 문장을 잇는 콜론(`colon`)을 표시합니다. 각 경고를 확인하고, 그대로 두기로 한 항목은 이유와 함께 보고합니다.

**문장 의미, 줄 내용의 재배열, MDX/HTML 문법의 유효성, 그림 동작, 실제 링크 이동은 보증하지 않습니다.** 결과가 통과해도 줄별 대조와 diff 검토가 필요합니다. 원문에 이미 있던 문제(heading과 맞지 않는 내부 링크 등)는 새로 생긴 문제와 구분해 보고합니다.

4. `git diff --check`, 파일별 diff, 변경 파일 목록을 확인합니다. 본문 담당 범위와 배정된 그림 밖의 변경을 섞지 않습니다. 그림은 화면과 동작을 확인하고, MDX 문법 변경 위험이 있으면 저장소의 빌드로 확인합니다. 실행하지 못한 검증은 미확인으로 표시합니다.
5. 여러 모델 검토는 사용자가 요청했거나 필요성과 범위가 합의된 경우에 사용합니다. 모델을 고정하지 않습니다. 지정 모델이 없으면 그 사실을 알리고 임의 대체하지 않습니다. 각 검토자는 같은 고정 원문을 독립적으로 읽고, 통합자는 지적의 근거와 충돌을 재확인합니다.

마지막에는 처리한 본문·그림 범위, 실행한 검증, 남은 WARN과 판단 근거, 새로 정한 용어, 남은 해석·원문 문제를 간결히 보고합니다. 리뷰에서는 심각도와 정확한 줄, 짧은 원문·번역, 수정 제안을 붙입니다. 검증하지 않은 것을 “모두 정상”이라고 단정하지 않습니다.
